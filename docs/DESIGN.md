# Game Design Document & Technical Architecture Spec

**Проект:** Story-driven Card RPG / Tavern Management
**Движок:** Godot 4 · GDScript
**Визуальный стиль:** Static 2D с эффектом параллакса (слои фонов, персонажей и объектов).
**В игре всегда ночь:** цикла день/ночь нет, атмосфера строится на свечах, лампах,
каминах и тёплом свете на тёмно-синем фоне (см. концепт-скетчи комнат, §4.0).
**Статус документа:** черновик, решения фиксируются в §8

## 1. Общая концепция и Core Game Loop

- **Жанр:** Story-driven Card RPG / Tavern Management.
- **Визуальный стиль:** Static 2D с эффектом параллакса (слои фонов, персонажей и объектов).

**Игровой цикл (Core Loop):**

1. **Кабинет (Карта мира):** выбор боевой или сюжетной точки.
2. **Бой:** пошаговый бой (30 карт в колоде, +1 маны за ход до 10, лимит руки 10 карт).
   Рука в бою отдельная: в начале боя она пустая, карты добираются из боевой колоды.
3. **Возврат в таверну:** после боя при любом исходе игрок возвращается в таверну.
   **Смены дня нет** (решение 2026-10-24): цикла день/ночь в игре нет, всегда ночь.
   Единственное последствие поражения — одноразовые карты, реально разыгранные
   в бою, сгорают навсегда (см. §5).
4. **Фаза Таверны** (идёт постоянно, параллельно с таймерами сада):
   - **Сад:** созревание растений по коротким реальным таймерам (минуты, см. §4.5).
   - **Мастерские (Кухня, Кузня, Алхимия, Библиотека):** крафт карт по рецептам.
   - **Барная стойка:** обслуживание клиентов, выполнение заказов.
   - **Лавка:** торговля с торговцем.
   - **Казармы:** сборка боевых колод из существ и остальных карт коллекции.

## 2. Модуль 1: Архитектура данных (Godot Custom Resources)

Все скрипты ресурсов находятся в `res://scripts/resources/`.

### 2.1. Базовый класс: `CardData.gd`

```gdscript
class_name CardData
extends Resource

enum CardType {
	CREATURE,    # Существо (постоянная)
	SPELL,       # Заклинание (расходная)
	ITEM,        # Предмет (расходная)
	INGREDIENT,  # Ингредиент (крафт)
	FOOD,        # Еда (расходная / для клиентов)
	DRINK,       # Напиток (расходная / для клиентов)
	SEED,        # Семена (для сада)
	POTION,      # Зелье (расходная)
	RECIPE,      # Рецепт (для изучения в книгах)
	QUEST        # Задание (для активации в кабинете)
}

@export var id: String = ""
@export var title: String = ""
@export_multiline var description: String = ""
@export var icon: Texture2D
@export var card_type: CardType
@export var is_consumable: bool = false
@export var buy_price: int = 0
@export var sell_price: int = 0
```

### 2.2. Система эффектов: `CardEffect.gd`

```gdscript
class_name CardEffect
extends Resource

enum EffectType {
	DAMAGE, HEAL, ARMOR, DRAW_CARD, DISCARD,
	BUFF_ATTACK, BUFF_HEALTH, SUMMON, FREEZE, DESTROY_TARGET
}

enum TargetType {
	SINGLE_ENEMY, ALL_ENEMIES, SINGLE_ALLY, ALL_ALLIES, SELF_HERO, ENEMY_HERO, ANY_TARGET
}

@export var effect_type: EffectType
@export var target_type: TargetType
@export var value: int = 0
```

### 2.3. Дочерние классы карт

- **`CreatureCardData.gd`** — `mana_cost`, `attack`, `health`, `max_health`, `keywords`.
- **`ConsumableCardData.gd`** — `mana_cost`, `stack_limit`, `effects`, `craft_recipe`.
- **`SeedCardData.gd`** — наследник `ConsumableCardData`, содержит `harvest_result_card: CardData`.

## 3. Модуль 2: Глобальные менеджеры (Autoloads)

1. **`InventoryManager.gd`** — хранит `archive_inventory: Dictionary` (Архив со стаками
   расходников, «главное хранилище» всех карт таверны) и `current_hand`
   (один общий веер игрока до 10 карт на все комнаты, §6.5).
2. **`PlayerManager.gd`** — состояние игрока: **золото** (отображается в левом нижнем
   углу рядом с аватаром), здоровье, уровень и опыт, счётчики ресурсов.
3. **`GameStateManager.gd`** — режимы игры (`TAVERN`, `WORLD_MAP`, `BATTLE`).
4. **`RoomManager.gd`** — переходы между комнатами (см. §6).
5. **`SaveManager.gd`** — автосейвы: между комнатами (перезапись одного слота)
   и отдельный автосейв перед боем (см. §6.6).
6. **`GardenManager.gd`** — состояние сада: 8 горшков и deadline-таймеры
   созревания; живёт вне сцены сада, поэтому растения растут, пока игрок
   в других комнатах (реализовано на этапе 4).
7. ~~`DayManager.gd`~~ — **удалён**: цикла дня/ночи нет, в игре всегда ночь.
   Сад работает на реальных таймерах, а не на смене дня (§4.5).

## 4. Модуль 3: Визуальный дизайн и механики локаций таверны

### 4.0. Общий визуальный язык комнат (по концепт-скетчам автора)

Автор предоставил 9 концепт-скетчей: Алхимия, Казармы (на скетче — «Архив»), Барная стойка, Библиотека,
Кабинет, Кузня, Кухня, Лавка, Сад. У всех комнат единая композиция экрана (16:9):

- **Верхние ~3/4 экрана** — иллюстрация комнаты. В центре главный интерактивный
  объект: котёл (Алхимия), магический круг (Библиотека), наковальня и рабочий стол
  (Кузня), разделочный стол и котёл (Кухня), горшки на стеллажах (Сад), витрины
  и торговец (Лавка), гость за стойкой (Бар), карта во всю стену (Кабинет).
- **Справа вверху** — панель контекста: рецепт с ингредиентами (мастерские),
  активные задания (Кабинет), «Мои колоды» (Казармы).
- **Справа на столе** в мастерских — открытая книга рецептов (`DropZone`, см. §4.1).
- **Нижняя полоса — постоянный интерфейс** (одинаковый во всех комнатах):
  слева аватар персонажа, здоровье, уровень/опыт, золото и счётчики ресурсов;
  по центру веер карт руки; справа рубашкой вверх — колода (вход в Архив);
  крайний справа — **деревянный указатель с вороной** (навигация по комнатам, §6.3).
- **Всегда ночь:** тёмно-синяя палитра, тёплый свет свечей/ламп/каминов,
  луна в окнах. Дневных вариантов графики не делаем.

Исключения из общей сетки: Кабинет (карта занимает почти весь экран, нижняя
полоса минимальна) и бой (отдельный полноэкранный режим, §5 и §6.2D).

### 4.1. Система книг (активация рецептов и заданий)

Во всех мастерских и кабинете книги выступают в роли `DropZone`:

- Перетаскивание карты типа `RECIPE` на Книгу Рецептов сжигает карту и добавляет рецепт в список изученных.
- Перетаскивание карты типа `QUEST` на Книгу Заданий сжигает карту и активирует новую точку/миссию на Карте Мира.

### 4.2. Барная стойка (`BarScene.tscn`)

- **Визуал:** стойка бара, камин, стеллажи с бутылками.
- **Механики:**
  - Индикатор-колокольчик внизу экрана уведомляет о новом госте.
  - Диалоговое окно слева и интерактивные опции диалога справа.
  - При нажатии «Завершить» проигрывается покадровая комикс-анимация ухода гостя.
  - Предупреждающее окно при попытке завершить диалог с необслуженным клиентом.

### 4.3. Шаблон ремесленных комнат (`CraftRoomTemplate.tscn`)

- **Кухня:** разделочный стол (`DropZone`), книга кулинарных рецептов, висящий на стене виджет текущего заказа. Крафт еды/напитков.
- **Кузня:** стол ремесленника (`DropZone`), чертёжная книга, виджет заказа. Крафт снаряжения и предметов (`ITEM`).
- **Алхимия:** бурлящий котёл (`DropZone`), гримуар зелий, виджет заказа. Крафт эликсиров и зелий (`POTION`).
- **Библиотека:** магический круг с кристаллами (`DropZone`), фолиант заклинаний, виджет заказа. Крафт свитков и магии (`SPELL`).

### 4.4. Лавка торговца (`ShopScene.tscn`)

- **Покупки:** витринные полки с картами и ценниками. Клик по карте перемещает её в Руку, отправляя золото торговцу.
- **Продажа:** перетаскивание карты из Руки на торговца (`DropZone`). Все карты в веере имеют бирки цен.
- **Фильтр:** Архив открывает инвентарь с ценами для выборки карт в Руку перед продажей.

### 4.5. Сад (`GardenScene.tscn`)

- **Посадка и полив:** стеллаж с горшками (`DropZone`). Перетаскивание карты `SeedCardData` сажает росток, перетаскивание Воды/Лейки запускает таймер созревания.
- **Созревание — по короткому реальному таймеру** (порядок — минуты, как на скетче:
  0:58–5:16; точные значения по растениям — баланс, см. §7). Смены дня нет, поэтому
  таймер нельзя «абузить» проигрышами: он идёт сам, пока игрок занят другими комнатами.
- Технически таймер хранится как момент готовности (deadline) в состоянии сада,
  а не как узел `Timer` внутри сцены сада: сцена выгружается при переходе в другую
  комнату, а растение должно продолжать расти.
- **Сбор урожая:** клик по созревшему растению отправляет карту урожая в общий веер,
  а при полном веере — автоматически в Архив (§6.5). Сбор никогда
  не блокируется полным веером.

### 4.6. Кабинет (`CabinetScene.tscn`)

- **Карта мира:** фэнтезийная карта во весь экран с точками интереса, замками и ресурсами.
- **Интерфейс:** вкладки фильтров сверху, виджет активных заданий справа и книга квестов (для сброса карт `QUEST`). Окно точки содержит сложность, награды, выбор колоды и кнопку «В БОЙ».

### 4.7. Казармы (`BarracksScene.tscn`)

Комната, где боевые существа ждут боя. Не путать с Архивом: Архив — общее
хранилище всех карт и не является комнатой (открывается панелью у веера).

- **Сборка колод:** сетка карт с пагинацией (страницы `1/2`), фильтры по мане (`0-6+`) и вкладки типов карт (`Существа`, `Заклинания`, `Предметы`, `Зелья`, `Еда`).
- **Панель колод:** блок справа со списком сохранённых 30-карточных колод для боевых миссий.

## 5. Модуль 4: Боевой движок (`BattleManager.gd`)

- Формат Hearthstone: 2 героя, 30 карт в колоде, +1 маны за ход до 10.
- **Рука боя отделена от таверны полностью:** бой начинается с пустой рукой,
  карты добираются из боевой колоды по правилам боя. Таверная рука на время
  боя заморожена и не используется.
- Разыгранные одноразовые карты (`is_consumable = true`: предметы, заклинания,
  еда, зелья) **сгорают навсегда** — они списываются из Архива независимо от исхода.
  Сгорают только реально разыгранные карты; не разыгранные возвращаются.
- Постоянные карты существ (`is_consumable = false`) не сгорают никогда:
  это коллекционные карты как в Hearthstone, после боя они полностью
  восстанавливаются и остаются в коллекции/колоде.
- **Смены дня после боя нет.** После любого исхода игрок возвращается в таверну.
  Отдельного штрафа за поражение, кроме сгоревших в бою одноразовых карт,
  на текущий момент не предусмотрено (награды за победу — см. §7).
- Перед боем делается отдельный автосейв (см. §6.6).
- **Бой — отдельный полноэкранный экран с загрузкой** (утверждено 2026-10-24):
  сцена `BattleScene.tscn` не является комнатой таверны и не живёт в её оболочке.
  При нажатии «В БОЙ»: предбоевой автосейв → экран/переход загрузки → бой.
  После боя: переход с загрузкой обратно в таверну, в комнату запуска (Кабинет).
  Подробности перехода — в §6.2D.

## 6. Модуль 5: Навигация между комнатами и рука карт в таверне

> **Статус: УТВЕРЖДЕНО (2026-10-24).** Навигация — указатель с вороной (§6.3);
> технический вариант — **D** (§6.2): таверна в сцене-оболочке, бой —
> отдельный полноэкранный экран с загрузкой; веер в таверне — **один общий**
> на все комнаты (§6.5), нижняя панель при смене комнат не меняется.

### 6.1. В чём задача

Комнат много: бар, сад, лавка, архив, кабинет и четыре мастерские
(кухня, кузня, алхимия, библиотека), плюс карта мира и бой.
Игрок переключается между ними постоянно, и почти везде ему нужны карты
(крафт, продажа, посадка — всё через перетаскивание карт), а также нижняя
полоса интерфейса: профиль с золотом, рука, колода и указатель (§4.0).

Есть три разных вопроса, их важно не путать:

1. **Технический** — как игра внутри устроена и загружает комнаты.
2. **Игровой** — что видит и нажимает игрок, чтобы перейти в другую комнату.
3. **Рука в комнатах** — какие карты лежат в веере в каждой комнате (§6.5).

### 6.2. Техническая часть: как загружать комнаты

#### Вариант A. Полная смена сцены — `change_scene_to_file()`

Каждая комната — отдельная сцена, Godot полностью заменяет одну другой.
Состояние игры живёт в Autoload-менеджерах и поэтому не теряется.

- ➕ Самый простой вариант, встроен в Godot, ничего изобретать не надо.
- ➕ Каждая комната — отдельный файл: легко открывать, тестировать и править по отдельности.
- ➖ Руку карт, верхнюю панель и колокольчик придётся создавать заново в каждой комнате
  (или выносить в отдельный Autoload-интерфейс, что усложняет).
- ➖ Параметры перехода («открыть Архив в режиме продажи из Лавки», «вернуться туда,
  откуда пришёл») приходится передавать через менеджеры вручную.

#### Вариант B. Одна главная сцена-оболочка + комнаты внутри неё

Есть одна постоянная сцена `Main.tscn`. Внутри неё — «слот», куда загружается
текущая комната, а вокруг — постоянный интерфейс: нижняя полоса (профиль,
золото), рука карт и колокольчик. Комнаты при этом остаются отдельными файлами сцен.

- ➕ Рука и верхняя панель существуют в одном экземпляре и не пересоздаются —
  а Рука нужна почти в каждой комнате.
- ➕ Можно делать плавные переходы (затемнение, сдвиг) и держать поверх комнаты
  всплывающие окна — например, Архив поверх Лавки.
- ➕ Параметры перехода и «вернуться назад» делаются одним менеджером переходов.
- ➖ Архитектуры чуть больше: нужен менеджер комнат и общее правило для комнат
  («комната сообщает, когда в неё вошли и когда вышли»).
- ➖ Комнату нельзя просто запустить одну клавишей F6 — для теста нужен
  маленький тестовый стенд или запуск через `Main.tscn`.

#### Вариант C. Все комнаты в одной гигантской сцене

Все комнаты лежат в одной сцене и просто включаются/выключаются (видимость узлов).

- ➕ Переключения мгновенные, загружать ничего не надо.
- ➖ Сцена быстро станет огромной и неудобной: 10+ комнат в одном файле.
- ➖ В Git этот файл будут дёргать все правки подряд — конфликты и неразбериха.
- ➖ Редактор Godot начнёт тормозить, а новичку — тяжело не запутаться в дереве узлов.
- **Не рекомендуется.**

#### Вариант D. Гибрид (УТВЕРЖДЕНО)

Оболочка как в варианте B — для всех комнат таверны, но **бой — отдельный
полноэкранный экран с загрузкой**: при старте боя делается предбоевой автосейв,
показывается экран/переход загрузки, таверна и её интерфейс полностью
скрываются/выгружаются, бой стартует с пустой рукой и добором из боевой колоды.
После боя — обратный переход с загрузкой в таверну, в комнату, из которой ушли
в бой (Кабинет). Экран загрузки здесь — не искусственная задержка, а честный
переход: затемнение/индикатор на время смены сцены и подготовки боя
(ориентир — от ~0,3–0,5 с, чтобы переход читался, а не мигал).

- ➕ Таверна получает все плюсы варианта B.
- ➕ Бой не тянет за собой интерфейс таверны: рука боя отдельная, начинается
  пустой и набирается из боевой колоды (решено, см. §5).
- ➕ Каждая комната и бой по-прежнему отдельные файлы сцен.
- ➖ Нужно чётко договориться, что хранится в Autoload-менеджерах (золото,
  инвентарь, таймеры сада), а что живёт только внутри комнаты — иначе состояние «потеряется»
  при переходе. Это решается правилом: **всё, что должно пережить переход,
  хранится в менеджерах, а не в комнате.**

**Итог: утверждён вариант D.** Он ненамного сложнее варианта A,
но избавляет от главной будущей боли — дублирования руки и нижней полосы
интерфейса в каждой из 9+ комнат, а веер и панель делаются
в одном месте — в постоянной оболочке.

Пример структуры:

```
Main.tscn                  — постоянная оболочка
├── RoomSlot               — сюда загружается текущая комната
└── PersistentUI (CanvasLayer)
    ├── ProfileUI          — аватар, здоровье, LV/опыт, золото и ресурсы (левый нижний угол)
    ├── HandUI             — веер карт руки текущей комнаты (см. §6.5)
    ├── DeckShortcut       — колода рубашкой вверх: открыть Архив поверх комнаты (§6.5)
    ├── BellIndicator      — колокольчик новых гостей
    └── SignpostNav        — указатель с вороной: навигация по комнатам (§6.3)

scenes/rooms/BarScene.tscn        ┐
scenes/rooms/GardenScene.tscn     │ каждая комната — отдельный файл,
scenes/rooms/KitchenScene.tscn    │ загружается в RoomSlot и выгружается
...                               ┘ при уходе
scenes/battle/BattleScene.tscn    — бой, отдельный полноэкранный режим
```

Переход выполняет один менеджер (`RoomManager`): `go_to_room(room_id, params)`,
он же помнит предыдущую комнату для кнопки «назад» и шлёт сигнал
`room_changed`, чтобы интерфейс мог, например, подсвечивать текущую вкладку.

### 6.3. Игровая часть: как игрок переключается (РЕШЕНО)

**Дорожный указатель с вороной в правом нижнем углу** — он есть на всех
концепт-скетчах комнат (см. §4.0). Это и есть панель навигации:

- **Все дощечки видны всегда.** Раскрывающийся список отклонён автором
  при проверке этапа 2: игрок перемещается постоянно, и лишний клик
  «открыть список» на каждый переход — лишнее трение. Переход — в один клик,
  как на примере автора с дощечками вокруг указателя.
- **Каждая комната — отдельная дощечка.** Мастерские не сворачиваются в одну
  общую вкладку: Кухня, Кузня, Алхимия и Библиотека — четыре отдельные
  дощечки одним столбцом («все по отдельности, но рядом»); вторым столбцом —
  Бар, Сад, Лавка, Кабинет, Казармы.
- Указатель — часть постоянного интерфейса оболочки (`PersistentUI` в
  `Main.tscn`): он один на всю игру и накладывается поверх текущей комнаты,
  а не дублируется внутри каждой сцены комнаты.
- Текущая комната подсвечена и не кликабельна. На дощечки можно вешать значки
  событий: «созрело в саду», «новый гость в баре» — для этого указатель
  слушает сигнал `room_changed` и состояния менеджеров.
- Ворона — маскот навигации: сидит на указателе; реакции/подсказки вороны —
  атмосферная деталь на будущее, механики не требует.

Рассмотренные альтернативы: раскрывающийся список дощечек (отклонён автором:
лишние клики), двери/стрелки внутри комнат (атмосферно, но с 9 комнатами
игрок потеряется; можно добавить позже как второй, необязательный способ —
технически это тот же вызов `RoomManager.go_to_room(...)`) и план здания
(лишний экран и клик на каждое перемещение).

### 6.4. Решения по этому разделу

Все три вопроса закрыты: технический вариант — **D** (§6.2),
игровой способ — **указатель с вороной** (§6.3), веер в таверне — **один общий** (§6.5).
Оставшиеся мелкие вопросы — в §7.

### 6.5. Веер карт в таверне (РЕШЕНО: один общий веер)

> **Статус: УТВЕРЖДЕНО 2026-10-25.** Это решение **отменяет** прежнюю
> систему A+ «своя рука у каждой комнаты» от 2026-10-24.

**Как устроено теперь**

- У игрока **один общий веер** (`InventoryManager.current_hand`, до 10 карт)
  на всю таверну. В какой бы комнате игрок ни был, в веере лежат одни и те
  же карты — в том же порядке.
- При смене комнаты меняется **только сцена комнаты**. Вся нижняя панель
  (профиль, веер, колода, указатель) всегда одна и та же и никуда не уезжает.
- Архив — главное хранилище. Ненужное сбрасывается в Архив, нужное берётся
  из Архива — для этого у нас удобная панель Архива (см. ниже). Поэтому
  отдельная рука на комнату больше не нужна.

**Почему отказались от A+ (своя рука у каждой комнаты)**

Главная причина автора: добыча не привязана к комнате. В саду игрок собирает
растения и получает карты, которые нужны, например, в алхимии или библиотеке.
При руках по комнатам эти карты «оставались» в веере сада, и игроку приходилось
возвращаться за ними. С одним веером игрок просто уносит карты с собой в любую
комнату — а лишнее в один клик сбрасывает в Архив.

**Панель Архива поверх комнаты**

**Модель ввода (утверждено 2026-10-25, этап 5):** в Архиве карты
перекидывают **кликами** — так быстрее, чем таскать. Во всех остальных
местах карты **таскают мышью** на объекты комнат: горшок сада, стол
крафта, гостя за стойкой. Игрок должен чувствовать, что «рукой положил»
карту. Каждый объект-цель сам объявляет, какие карты принимает, и
подсвечивается, когда над ним держат подходящую карту. Обычные клики
в комнатах остаются только для действий без карт (собрать урожай,
кнопки, диалоги). Пилотная реализация — сад; столы крафта и гости
подключатся к тому же шаблону, когда появятся их механики.

- Открыть Архив можно **из любой комнаты**, не уходя для этого в Казармы:
  по клику на колоду Архив открывается **панелью на фоне комнаты, над веером**
  (не на весь экран). В панели карты того же размера, что в веере;
  количество «×N» — в правом верхнем углу карты. Отдельной руки внутри
  панели нет: рука игрока — веер внизу, он остаётся кликабельным.
- Клик по карте в панели — карта «улетает» полётом в веер.
- Клик по карте веера (пока панель открыта) — карта улетает полётом в Архив.
- Казармы при этом остаются отдельной комнатой — полноценным экраном для
  сборки боевых колод (там нужна большая сетка, §4.7).

**Остальные правила веера и Архива**

- Новая добыча (урожай, результат крафта, покупка) сначала падает в общий
  веер, а если веер полон — **автоматически уходит в Архив** с подписью
  «Архив +1 …». Сбор урожая никогда не блокируется полным веером.
- По выбранному рецепту кнопка «Подобрать ингредиенты» сама докладывает
  недостающие карты из Архива в веер.
- Учёт без дублей: карта в веере «в кармане» у игрока и в Архиве не числится.

#### 6.5.1. Анимации веера

Веер не меняется при смене комнаты, поэтому анимаций смены руки по комнатам
больше нет. Остаются анимации только там, где состав веера реально меняется:

1. **Первый вход в игру:** веер вылезает снизу и раскладывается на своё
   место (карты со стаггером ~20–30 мс, мягкая остановка ease-out).
2. **Карта из Архива в веер:** летит от своей ячейки в панели Архива на
   своё место в веере; остальные карты веера плавно сдвигаются/сжимаются.
3. **Карта из веера в Архив:** летит вверх к панели Архива, остальные карты
   веера плавно занимают освободившееся место.
4. **Пустой веер** показывается плашкой с подсказкой открыть Архив —
   тем же выездом снизу, а не появлением из ниоткуда.
5. Во время любой анимации карты веера неактивны (нельзя схватить карту
   «в полёте»).

Технически: веер — один постоянный `HandUI` в оболочке `Main.tscn`.
Данные — `InventoryManager.current_hand: Array[CardData]`, состав веера
сохраняется в сейв (§6.6). Смена комнаты веер не перестраивает.

### 6.6. Сохранения (РЕШЕНО в общих чертах)

- **Автосейв между комнатами:** при каждом переходе между комнатами игра
  автоматически сохраняется в один и тот же слот (перезапись). Реализуется
  в `RoomManager.go_to_room(...)` через `SaveManager`.
- **Отдельный автосейв перед боем:** перед стартом боя пишется отдельный слот,
  который комнатные автосейвы не затирают (точка возврата «перед боем»).
- Что обязано попадать в сейв: Архив и общий веер (§6.5), золото и состояние
  игрока, открытые рецепты/задания, состояние сада (deadline созревания каждого
  горшка), текущая комната.
- Ручные сохранения и количество слотов — не решено (см. §7).
